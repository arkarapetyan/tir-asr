## Facts and hints for C7

- **`#err` [UNVERIFIED]:** a first check is the Seamless vocabulary. Aren can run, in the project folder, `HF_HUB_OFFLINE=1 uv run --no-sync python -c "from transformers import AutoProcessor; t = AutoProcessor.from_pretrained('facebook/seamless-m4t-v2-large', local_files_only=True).tokenizer; print([w for w in t.get_vocab() if 'err' in w.lower()][:40])"`. If `#err` is a token, the model writes it; else it comes from the decode or the terminal.
- **English text in the HY line [UNVERIFIED]:** the `hye` row of the decode can give English for some audio (the model translates in place of a transcription). A recorded run shows for which segments; the HY line of P1 for the same speech is the reference.
- **The capture gap (Q-10):** with P4 in the worker, a capture thread waited up to 145 ms (P1: under 50 ms). The test process had `torch CPU threads 4` after a second model load (the program has 1). PulseAudio keeps the audio in its buffer, so lost audio is not expected [UNVERIFIED]. A possible cause: the Python loop of `generate` holds the interpreter lock (GIL) [UNVERIFIED].
- **Recorded live test:** run P1 and P4 on the same call with `./run.sh … 2>&1 | tee -i test-results/c7-l07-p1.txt` and `… --seamless … | tee -i test-results/c7-l07-p4.txt`. With the same speech for both, a recording of the call sides is best (then both runs get the same audio, for example through the null sinks of the sim tests).
- D-056 question 4 is answered: the slow CPU lines of C3 came from 24 threads on 8 fast and 16 slow cores. The model is greedy.
- With P4, the line totals are about 0.85 s (P1 about 0.63 s).
